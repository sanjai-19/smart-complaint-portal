Phase 1: Define

Introduction & Industry Domain Background

Domain Overview
Campus Redressal Needs

Modern higher educational institutions accommodate thousands of resident students across academic, hostel, and infrastructure facilities requiring immediate redressal.

The Role of SLAs

Service Level Agreements (SLAs) establish strict resolution deadlines (e.g., 48 Hours) to replace informal, unmonitored communication with quantifiable metrics.

Citizen Charters

Transparent tracking, automated escalation, and mandatory satisfaction scoring empower students while establishing administrative accountability.

Key Industry Drivers for Modern Grievance Portals
  • ✓Shift from Physical to Digital: Eliminating physical complaint boxes in favor of real-time multi-device accessibility.
  • ✓Zero Accountability in Email Threads: Overcoming informal emails where tickets get buried or lost with no assigned ownership.
  • ✓Enforced Governance: Implementing systematic escalation hierarchies ensuring institutional leaders (HODs/Deans) intervene on delayed tickets.
Phase 1: Define

Problem Statement & Real-World Inefficiencies

Problem Analysis

Official Problem Statement

"Campus and civic grievance redressal processes are fragmented across paper complaint boxes and unmonitored emails, resulting in untracked complaint escalations, delayed resolutions, and zero accountability for administrative officers."

🚨 Critical Real-World Pain Points
  • ✕Untracked Complaints: Grievances submitted via paper drop boxes lack reference IDs, audit trails, and timestamps.
  • ✕Delayed Resolutions: Urgent hazards (electrical shock, water pipe burst) sit unattended for days without prioritization.
  • ✕Zero Staff Accountability: No automated mechanism exists to trace which officer was responsible for resolving an issue.
  • ✕Information Asymmetry: Students have no visibility into the status of their requests once dropped in a box.
🎯 Impact on Stakeholders
  • •Students: Frustration due to unresolved living conditions and lack of communication.
  • •Department Coordinators: Overwhelmed with unorganized paper slips and duplicate complaints.
  • •HODs & Deans: Blind to chronic bottlenecks until escalations explode into severe campus disruptions.

Phase 2: Design

Application Modules Breakdown

Modular Decomposition
1. Auth & RBAC

Manages user registration, BCrypt password hashing, and role switching across STUDENT, COORDINATOR, HOD, DEAN, ADMIN.

2. Grievance Submission

Captures title, description, category, and photo proofs with client-side canvas compression and dynamic priority badges.

3. Priority Router

Keyword-based heuristic engine classifying emergency hazards into HIGH, maintenance issues into MEDIUM, and inquiries into LOW.

4. SLA Tracking Engine

Computes 48-hour resolution deadline (created_at + 48h) with live 1-second interval ticking countdown and color bar.

5. Auto-Escalation Daemon

Background scheduler periodically identifying breached tickets and promoting them from Coordinator to HOD, then Dean.

6. Verification & Rating

Enforces closed-loop governance: staff records "Action Taken", but status transitions to RESOLVED only upon student's 1–5 star rating.

Database Design (3NF Schema & Constraints)

MySQL Schema
Table Name Column Name Data Type Constraint Description
users id INT AUTO_INCREMENT PRIMARY KEY Unique user surrogate identifier
users email VARCHAR(150) UNIQUE, NOT NULL Unique login email address
users role VARCHAR(30) DEFAULT 'STUDENT' STUDENT, COORDINATOR, HOD, DEAN, ADMIN
complaints id INT AUTO_INCREMENT PRIMARY KEY Unique complaint identifier
complaints reference_id VARCHAR(50) NOT NULL Formatted tracking key (CMP-XXXXXX)
complaints user_id INT FOREIGN KEY (users.id) Relational linkage to student user
complaints priority / status VARCHAR(20) / (50) NOT NULL Priority (HIGH/MED/LOW) & Workflow State
complaints attachment_path LONGTEXT NULL Base64 encoded photo or document proof
complaints sla_deadline TIMESTAMP NULL 48-Hour resolution deadline (created_at + 48h)
complaints rating / feedback INT / TEXT NULL Mandatory student satisfaction (1 to 5 stars)

3NF Compliance: All tables are in Third Normal Form (3NF). Every non-key attribute is non-transitively dependent exclusively on the primary key, eliminating insertion, deletion, and update anomalies.

Java Backend Engine & DAO Architecture

Backend Engineering
Controller / Handler Layer
  • •HttpServer (Port 8080): Natively binds contexts for auth, complaints, tracking, and actions.
  • •Thread Pool: Backed by Executors.newFixedThreadPool(10) for non-blocking concurrent request handling.
  • •CORS Interceptor: Sets standard Access-Control headers on every response.
Data Access Object (DAO) Layer
  • •ComplaintDAO.java: Handles CRUD operations, priority heuristics, and SLA deadline generation.
  • •UserDAO.java: Validates user credentials using BCrypt.checkpw().
  • •DatabaseConnection.java: Manages JDBC connections, auto-creates tables, and seeds demo accounts.

Phase 3: Develop

Database CRUD Operations & Parameterized SQL

SQL & JDBC
CREATE & READ Queries
-- Insert Complaint with 48h SLA Deadline INSERT INTO complaints (user_id, title, description, category, department, priority, status, attachment_path, assigned_coordinator, created_at, sla_deadline) VALUES (?, ?, ?, ?, ?, ?, 'Submitted', ?, ?, NOW(), DATE_ADD(NOW(), INTERVAL 48 HOUR)); -- Track Complaint by Reference ID SELECT c.*, u.name as user_name FROM complaints c JOIN users u ON c.user_id = u.id WHERE c.reference_id = ? OR c.id = ?;
UPDATE, ESCALATE & CLOSE Queries
-- Record Action Taken (Staff Pre-Closure) UPDATE complaints SET status = 'Action Taken', resolution = ? WHERE id = ?; -- Mandatory Student Rating to Finalize RESOLVED UPDATE complaints SET status = 'Resolved', rating = ?, feedback = ? WHERE id = ?; -- 48h SLA Auto-Escalation Query UPDATE complaints SET status = ?, escalation_level = ?, escalated_to = ? WHERE id = ?;

Security Enforcement: 100% of database interactions use java.sql.PreparedStatement with positional placeholders (?). This guarantees absolute immunity against SQL Injection attacks.
